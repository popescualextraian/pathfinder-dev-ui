# Backlog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `backlog` component next to `engine` that shows a project's items on configurable lanes, syncs with GitLab through a connector interface, and emits trigger events when a card is moved on the board.

**Architecture:** `backend/src/backlog` is its own package (`service/`, `integration/`, `repository/`, `index.ts`), importing only `commons/`, enforced by a boundary test like the engine's. The service owns `BacklogConnector` and the lane config; `GitlabConnector` implements it; `api/backlog` maps HTTP. GitLab is the source of truth, the backend polls into a local cache. The frontend adds a board next to the task UI through `api/backlog-api.ts` → `state/` → `views/`.

**Tech Stack:** NestJS, React/Vite, jest (+ supertest for e2e), `yaml` (new dependency), `fetch` for GitLab (no GitLab SDK).

**Spec:** `docs/superpowers/specs/2026-10-20-backlog-design.md`

## Global Constraints

- Node 22+; no new framework; the only new dependency is `yaml`.
- Lane ids and titles come from config only; no lane name ("plan", "test", …) in code outside tests and the example config.
- Tokens only via the environment (`tokenEnv` names the variable); never in YAML, API responses, logs or the cache file. Config errors name the key and never print values.
- `backlog` imports nothing from the backend but `commons/`; the rest of the backend imports it only from `backlog/index.ts`.
- Routes under `/api/backlog`; validation, logging and error mapping stay global (`app.setup.ts`); controllers hold HTTP concerns only.
- Cache file: mode 600 JSON in `BACKLOG_DATA_DIR`. Env vars: `BACKLOG_CONFIG` (unset means the component is off), `BACKLOG_DATA_DIR`.
- GitLab token scope `api`. GitLab test project: `moldovaa/vans-factory-rotation`, id 5829.
- Tests mirror the source tree: `backend/test/unit/backlog/...`, `frontend/test/...`; styling only with the CSS variables in `theme.css`.
- Poll default 60 s; `doneDays` default 14; a rejected move is 409; no manual order inside a lane (newest `updatedAt` first).

## Review Focus

1. An issue with two lane labels, or a closed issue that still carries a lane label: lane is the last configured lane, and `done` for a closed issue (Task 4).
2. The source is down or the token is rejected during a poll: the cache is kept, the board shows an error, nothing is emptied (Task 2).
3. More than 100 issues (GitLab pages): all are listed (Task 4).
4. A move where the source's lane differs from `from`: 409, no write, the cache is refreshed for that item (Tasks 2 and 4).
5. The token must not appear in `/api/backlog/*` responses, logs or the cache file (Tasks 3 and 5).
